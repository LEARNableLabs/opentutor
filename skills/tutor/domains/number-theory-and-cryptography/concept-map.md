# Number Theory and Cryptography — Concept Map

## Core Concepts (in learning order)

1. **Divisibility** — The foundation: when one integer divides another without remainder
2. **Division algorithm** — Every integer can be written as quotient times divisor plus remainder
3. **Greatest common divisor (GCD)** — The largest integer that divides both a and b
4. **Euclidean algorithm** — Efficient method to compute GCD using repeated division. Depends on: division algorithm
5. **Extended Euclidean algorithm** — Finds integers x, y such that ax + by = gcd(a,b). Depends on: Euclidean algorithm
6. **Bezout's identity** — The equation ax + by = gcd(a,b) always has integer solutions. Depends on: extended Euclidean algorithm
7. **Prime numbers** — Integers > 1 divisible only by 1 and themselves
8. **Fundamental theorem of arithmetic** — Every integer has unique prime factorization. Depends on: prime numbers
9. **Congruences** — a ≡ b (mod n) means n divides (a - b). Depends on: divisibility
10. **Modular arithmetic** — Arithmetic in residue classes modulo n. Depends on: congruences
11. **Modular inverse** — The value x where ax ≡ 1 (mod n). Depends on: extended Euclidean algorithm, modular arithmetic
12. **Linear congruences** — Solving ax ≡ b (mod n). Depends on: modular inverse
13. **Chinese Remainder Theorem** — System of congruences with coprime moduli has unique solution. Depends on: linear congruences
14. **Euler's phi function** — φ(n) counts integers from 1 to n that are coprime to n. Depends on: GCD, prime factorization
15. **Fermat's Little Theorem** — If p is prime, then a^(p-1) ≡ 1 (mod p) for any a not divisible by p. Depends on: modular arithmetic, primes
16. **Euler's Theorem** — a^φ(n) ≡ 1 (mod n) when gcd(a,n) = 1. Depends on: Euler's phi function, generalizes Fermat's Little Theorem
17. **Substitution ciphers** — Classical encryption by replacing characters. Depends on: modular arithmetic (for mathematical treatment)
18. **Key distribution problem** — Symmetric encryption requires secure channel for key exchange
19. **Public key cryptography** — Asymmetric encryption using public and private key pairs. Depends on: trapdoor functions
20. **Trapdoor functions** — Easy to compute one way, hard to reverse without secret. Depends on: computational hardness assumptions
21. **RSA key generation** — Choose primes p, q; compute n = pq, φ(n); choose e, d with ed ≡ 1 (mod φ(n)). Depends on: Euler's phi function, modular inverse
22. **RSA encryption/decryption** — Encrypt: c = m^e (mod n); Decrypt: m = c^d (mod n). Depends on: Euler's Theorem, modular exponentiation
23. **Modular exponentiation** — Efficiently computing a^k (mod n) using binary method. Depends on: modular arithmetic
24. **RSA security** — Based on hardness of factoring n = pq. Depends on: prime factorization, computational complexity
25. **Digital signatures** — Proving message authenticity using private key. Depends on: RSA encryption (reversed)
26. **Primality testing** — Determining if a number is prime without factoring. Depends on: Fermat's Little Theorem
27. **Fermat primality test** — Probabilistic test: if a^(n-1) ≢ 1 (mod n), then n is composite. Depends on: Fermat's Little Theorem
28. **Miller-Rabin test** — More reliable primality test, catches Carmichael numbers. Depends on: Fermat test, quadratic residues
29. **Integer factorization** — Breaking n into prime factors. Depends on: trial division, probabilistic algorithms
30. **Pollard's rho** — Probabilistic factorization algorithm. Depends on: birthday paradox, modular arithmetic
31. **Discrete logarithm** — Given g^x ≡ h (mod p), find x. Depends on: modular exponentiation, cyclic groups
32. **Cyclic groups** — Groups generated by a single element. Depends on: primitive roots, group theory
33. **Diffie-Hellman key exchange** — Two parties agree on shared secret using discrete log hardness. Depends on: discrete logarithm problem
34. **ElGamal encryption** — Public key system based on discrete logarithm. Depends on: Diffie-Hellman
35. **Elliptic curve cryptography** — Cryptography using elliptic curve groups instead of modular arithmetic. Depends on: discrete logarithm (on curves)
36. **Post-quantum cryptography** — Cryptosystems resistant to quantum attacks. Depends on: understanding limitations of RSA, discrete log under Shor's algorithm

## Dependencies

### Critical Paths

**Path to RSA:**
Divisibility → GCD → Euclidean algorithm → Extended Euclidean algorithm → Modular inverse → Linear congruences → Euler's phi function → Euler's Theorem → RSA

**Path to Diffie-Hellman:**
Modular arithmetic → Modular exponentiation → Cyclic groups → Discrete logarithm → Diffie-Hellman

### Key Bottlenecks

- **Extended Euclidean algorithm** is the computational bottleneck for finding modular inverses, which is essential for RSA key generation
- **Euler's Theorem** is the theoretical bottleneck — students must understand why a^φ(n) ≡ 1 (mod n) for RSA correctness proof
- **Modular exponentiation** is the implementation bottleneck — naive exponentiation is too slow; binary method is required
- **Discrete logarithm hardness** is the security bottleneck for Diffie-Hellman and ElGamal

### Concept Clusters

**Cluster 1: Divisibility Theory** (lessons 1-4)
GCD, Euclidean algorithm, primes, factorization — the foundation

**Cluster 2: Modular Arithmetic** (lessons 5-10)
Congruences, inverses, Fermat, Euler — the algebraic machinery

**Cluster 3: RSA** (lessons 14-18)
Key generation, encryption, decryption, signatures — the main application

**Cluster 4: Computational Hardness** (lessons 20-22)
Primality, factorization, complexity — why cryptography works

**Cluster 5: Alternative Systems** (lessons 23-27)
Discrete log, Diffie-Hellman, elliptic curves, post-quantum — beyond RSA

## Prerequisite Topics

- **Proof-based mathematics** — needed for Fermat's Little Theorem, Euler's Theorem, Chinese Remainder Theorem. Students must be comfortable with proof by induction, contradiction, and direct proof.
- **Modular arithmetic basics** — needed from lesson 1. Students should already know what "mod" means and how to compute a mod n.
- **Basic programming (Python or similar)** — needed for lessons 4, 16, 22. Students will implement Euclidean algorithm, RSA, and primality tests.
- **Group theory (optional but helpful)** — needed for discrete logarithm and elliptic curves. Can be introduced on-the-fly.

## Common Prerequisites Gaps

- **Binary exponentiation** — often not covered in intro programming courses, but essential for RSA implementation
- **Big integer arithmetic** — students may not realize that standard int types overflow for cryptographic parameters
- **Computational complexity** — understanding P vs NP helps motivate why factoring is hard, but often missing from math background
